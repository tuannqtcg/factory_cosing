# SESSION 2026-07-11 — Chuẩn bị Firebase Hosting (bổ sung/thay thế Render)
Pha hiện tại: 4 | Agent: Claude Code

## Đã quyết
- Không tạo ADR mới — đây là cấu hình deploy vận hành (tương tự `render.yaml`
  ở SESSION_2026-07-10), không phải quyết định kiến trúc nghiệp vụ/schema.
- Dùng **Firebase Hosting multi-site** (`"site": "bmcosting-app"` trong
  `firebase.json`) thay vì site mặc định của project — vì `bmcosting-ver-2`
  là project Firebase DÙNG CHUNG với nhiều app khác (`financial-suite`,
  `landingpage`, `sso-tcg`, `ai-studio-*`...), không rõ site mặc định
  (`bmcosting-ver-2.web.app`) đã bị app nào khác chiếm dụng chưa. Site riêng
  tên `bmcosting-app` (khớp tên service `bmcosting-app` đã dùng trong
  `render.yaml`) tránh đụng độ, an toàn hơn dùng site mặc định.

## Đã làm
- Thêm block `hosting` vào `firebase.json`: `public: "dist"` (khớp `outDir`
  trong `vite.config.ts`), rewrite SPA (`** → /index.html`), ignore file rác.
- Verify: `npm test` 328/328 xanh, `npm run typecheck` sạch, `npm run build`
  chạy thật ra `dist/index.html` + assets — khớp đúng cấu hình `public: dist`
  vừa thêm (không phải đoán suông).
- KHÔNG tự deploy — không có credentials Firebase CLI thật trong phiên này
  (đúng luật `AGENTS.md` §3: không secret/API key trong phiên; deploy thật
  cần user tự làm, giống ADR-016/017 trước đó).

## Còn treo / việc phiên sau (user tự làm — cần credentials thật)
1. **Tạo Hosting site trước khi deploy lần đầu** (site chưa tồn tại, deploy
   sẽ lỗi nếu bỏ qua bước này):
   ```
   firebase login
   firebase hosting:sites:create bmcosting-app --project bmcosting-ver-2
   ```
   Nếu tên `bmcosting-app` đã bị chiếm (site ID là global), đổi tên khác và
   sửa lại field `"site"` trong `firebase.json` cho khớp.
2. **Deploy**:
   ```
   npm run build
   firebase deploy --only hosting --project bmcosting-ver-2
   ```
   URL sau deploy: `https://bmcosting-app.web.app`.
3. **Thêm domain vào Firebase Auth → Authorized domains** — LƯU Ý site
   Hosting phụ (không phải site mặc định) KHÔNG tự động được thêm vào danh
   sách này, phải thêm tay `bmcosting-app.web.app` (và `.firebaseapp.com`
   nếu dùng), nếu không đăng nhập sẽ lỗi "unauthorized domain" — đúng rủi ro
   đã ghi ở SESSION_2026-07-10 cho phương án Render, áp dụng tương tự.
4. 4 biến `VITE_FIREBASE_*` cần có trong `.env` lúc `npm run build` (build
   local trước khi deploy, Firebase Hosting không có cơ chế inject env như
   Render Dashboard) — dùng đúng giá trị project `bmcosting-ver-2`.
5. Việc treo cũ từ SESSION_2026-07-10 vẫn còn nguyên (KHÔNG thuộc phạm vi
   phiên này): gọi thử `setUserRole` trên project thật để xác nhận
   `roleAudit` ghi đúng; thu hồi service account key đã upload phiên trước;
   quyết định dùng Render hay Firebase Hosting (hoặc cả 2) làm nơi phục vụ
   frontend chính thức — CHƯA hỏi/chốt với user trong phiên này, cần xác
   nhận trước khi coi Firebase Hosting là kênh deploy chính thức.

## Tiếp (cùng ngày) — Xác nhận render.yaml đã sẵn sàng Blueprint deploy

### Đã làm
- User yêu cầu deploy Render dạng **Blueprint** (khác "New Static Site" thủ
  công). Đối chiếu `render.yaml` hiện có (từ SESSION_2026-07-10) với field
  reference chính thức của Render Blueprint spec — đúng format: `type: web`
  + `runtime: static` (không phải `env: static` cũ), `staticPublishPath`,
  `buildCommand`, `envVars` với `sync: false` cho 4 biến `VITE_FIREBASE_*`.
  **Không cần sửa gì thêm** — file đã hợp lệ để Render tự nhận diện khi apply
  Blueprint.
- Không có `routes` SPA rewrite (đã kiểm tra `src/` — app không dùng
  react-router/BrowserRouter, chỉ 1 trang với tab-state nội bộ) nên không
  cần thêm rule fallback `index.html`.
- KHÔNG tự tạo Blueprint trên Render — không có Render API key/CLI/tài
  khoản trong phiên này (đúng luật không secret trong phiên).

### Còn treo — user tự làm trên Render Dashboard
1. render.com → **New +** → **Blueprint** → chọn (hoặc kết nối GitHub App
   nếu chưa từng authorize) repo `tuannqtcg/factory_cosing`.
2. Render tự đọc `render.yaml` ở root, hiện preview service `bmcosting-app`
   (Static Site) → bấm **Apply**.
3. Trong bước Apply (hoặc ngay sau, ở tab Environment của service), điền
   tay 4 biến đánh dấu `sync: false`: `VITE_FIREBASE_API_KEY`,
   `VITE_FIREBASE_AUTH_DOMAIN`, `VITE_FIREBASE_PROJECT_ID`,
   `VITE_FIREBASE_DATABASE_ID` — giá trị THẬT của project `bmcosting-ver-2`
   (Firebase Console → Project settings → SDK config).
4. Sau khi deploy xong, lấy domain Render cấp (`bmcosting-app.onrender.com`
   hoặc domain tùy chỉnh) → thêm vào Firebase Auth → Authorized domains
   (giống mục còn treo #3 ở trên cho Firebase Hosting — 2 kênh deploy đều
   cần bước này riêng).
5. Vẫn còn nguyên câu hỏi mục 5 phía trên: chưa chốt Render hay Firebase
   Hosting là kênh chính thức, hay dùng song song.
